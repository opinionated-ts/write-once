# Security Policy

## Supported Versions

Security fixes are provided for the latest released version of `write-once`. Upgrade to the latest version before reporting an issue when possible.

| Version        | Supported |
| -------------- | --------- |
| Latest release | Yes       |
| Older releases | No        |

## Reporting a Vulnerability

Please report suspected security vulnerabilities privately by emailing **[danhezcode@gmail.com](mailto:danhezcode@gmail.com)**. Do not disclose the issue publicly in a GitHub issue or discussion until it has been reviewed and a fix or mitigation can be coordinated.

Include as much of the following information as possible:

- The affected version and environment.
- A description of the vulnerability and its potential impact.
- Steps to reproduce the issue or a proof of concept.
- Any suggested mitigation, if known.

You should receive an acknowledgment within 7 days. We will investigate the report, assess its impact, and coordinate next steps with you where possible. Please allow time for a fix or mitigation before sharing details publicly.

## Scope

Reports are especially relevant to unintended file access or modification, unsafe handling of fragment markers or configuration, and other behavior that could compromise a user's project or data. Do not include real secrets or sensitive data in reports; use sanitized examples where possible.
